# POSTNEO Карточки — установка в отделении

Два способа поставить одно и то же приложение:

| | На одном компьютере | На сервере отделения |
|---|---|---|
| Что это | Папка с программой, запускается ярлыком, окно без адресной строки | Контейнер Docker, врачи заходят браузером по сети |
| Кому подходит | Один ординаторский компьютер, без ИТ-службы | Несколько рабочих мест с общей базой |
| Данные | `%LOCALAPPDATA%\POSTNEO\kart`, копия базы при каждом запуске | Том `/data`, бэкап по расписанию |
| Как собрать | `bash desktop/build-desktop.sh` → `dist/POSTNEO-Kartochki-win64-<версия>.zip` | `docker compose up -d --build` |
| Инструкция | `desktop/README.txt` внутри архива | ниже |

## Версия для одного компьютера

Архив содержит переносимый Node.js, серверную сборку и лаунчер
`POSTNEO-Kartochki.exe`, собранный на Go без консольного окна. Лаунчер
поднимает сервер на `127.0.0.1` со свободным портом, ждёт `/api/health`,
открывает окно Edge или Chrome в режиме `--app` и останавливает сервер,
когда окно закрыто. Запасной механизм: страница шлёт `/api/ping` раз в
10 секунд, без пингов 90 секунд сервер гасит себя сам. Интернет не нужен,
права администратора не нужны. Программа не подписана сертификатом, поэтому
SmartScreen при первом запуске попросит подтверждение.

Сборка требует node 22+, go 1.22+, zip и один раз доступ к nodejs.org за
`node.exe` (кэшируется в `desktop/.cache`). Проверка на Linux без Windows:
`bash desktop/build-desktop.sh linux`, затем `dist/postneo-kart-linux/postneo-kart`.

## Версия для сервера

Приложение для врачей отделения новорождённых: база пациентов, расчёт
парентерального питания и печатный лист назначений. Один контейнер Docker,
одна папка с данными, никаких внешних сервисов. В интернет не выходит.

## Что нужно

| | |
|---|---|
| Сервер | Linux с Docker 24+ и Docker Compose v2 (`docker compose version`). Подойдёт виртуальная машина: 2 ядра, 2 ГБ памяти, 10 ГБ диска |
| Сеть | Доступ врачей к серверу внутри больничной сети. Наружу порты открывать не нужно |
| HTTPS | Нужен сертификат: внутренний от ИТ-службы или Let's Encrypt, если у сервера есть доменное имя. Без HTTPS пароли и данные пациентов идут по сети открытым текстом |
| Браузер | Любой современный на рабочих местах: Chrome, Edge, Firefox, Safari. Телефон тоже подходит |

Данные пациентов — персональные данные и врачебная тайна (152-ФЗ). Сервер
должен находиться в больнице или в российском облаке по договору с
больницей как оператором. Резервные копии хранятся там же.

## Установка

```bash
# 1. Получить код
git clone https://github.com/jEw1IK/tpn.git
cd tpn/postneo-app
# либо распаковать переданный архив postneo-app.zip и зайти в папку

# 2. Собрать и запустить (сборка 2–4 минуты, нужен интернет только на этом шаге)
docker compose up -d --build

# 3. Проверить
curl http://127.0.0.1:3000/api/health      # {"ok":true,...}
```

Если на сервере нет интернета, образ собирают на другой машине и переносят:

```bash
docker build -t postneo-kart .            # там, где интернет есть
docker save postneo-kart | gzip > postneo-kart.tar.gz
# на сервере отделения
gunzip -c postneo-kart.tar.gz | docker load
docker compose up -d                       # без --build
```

## Первый вход

Откройте адрес приложения в браузере. Пока в базе нет пользователей, оно
покажет страницу первого запуска: логин и пароль администратора. Дальше
администратор заводит врачей и медсестёр в разделе «Пользователи».

Роли: врач ведёт пациентов и подписывает листы; медсестра смотрит и
печатает; администратор заводит людей, меняет пароли и может снять подпись
с листа. Сессия живёт 12 часов с последнего действия.

## HTTPS через ваш прокси

Контейнер слушает только `127.0.0.1:3000`. Перед ним ставится nginx или
Caddy с сертификатом. Пример nginx (сертификат от вашей ИТ-службы):

```nginx
server {
    listen 443 ssl;
    server_name kart.hospital.local;
    ssl_certificate     /etc/ssl/kart.crt;
    ssl_certificate_key /etc/ssl/kart.key;
    client_max_body_size 2m;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

Если нужно запустить приложение не в корне, а по пути вида
`https://сервер/kart/`, соберите образ с аргументом:
`BASE_PATH=/kart docker compose up -d --build` и в прокси направьте
`location /kart/` на тот же порт.

Для теста по обычному `http://` поставьте в `docker-compose.yml`
`COOKIE_SECURE: 0`, иначе браузер не примет cookie входа.

## Данные и резервные копии

Всё хранится в папке `data/` рядом с `docker-compose.yml`: файл
`postneo.sqlite` и его журнал `-wal`/`-shm`. Копировать файлы напрямую
можно только при остановленном контейнере; на работающем используйте
встроенную копию:

```bash
docker exec postneo-kart node scripts/backup.mjs /data/backups
```

Она кладёт целостный снимок `data/backups/postneo-ГГГГММДД-ЧЧММ.sqlite`
и хранит 30 последних. Ежедневно по cron:

```
15 3 * * * docker exec postneo-kart node scripts/backup.mjs /data/backups
```

Папку `data/backups` стоит дополнительно копировать на другой носитель.

Восстановление: остановить контейнер, положить копию на место
`data/postneo.sqlite` (удалив `-wal` и `-shm`), запустить.

## Обновление

```bash
git pull                   # или распаковать новый архив поверх
docker compose up -d --build
```

Схема базы обновляется сама при старте. Откат: вернуть старый код и
запустить снова; данные не трогаются.

## Где что лежит и как смотреть

| Команда | Что делает |
|---|---|
| `docker compose ps` | состояние контейнера, healthcheck |
| `docker compose logs -f` | журнал приложения |
| `docker compose restart` | перезапуск |
| `docker compose down` | остановить; данные в `data/` остаются |
| раздел «Журнал» в приложении | кто что открыл, изменил, подписал, с какого IP |

## Что умеет

- Карточка пациента: фамилия, № истории, дата и время рождения, пол, ГВ,
  масса при рождении, дата поступления, диагноз. Сутки жизни и ПКВ
  считаются от даты рождения.
- Взвешивания по датам, динамика массы.
- Лист на дату: берёт вчерашний лист целиком, подставляет массу при
  рождении, вчерашнюю и сегодняшнюю массу, активные препараты. Врач
  вписывает новое и подписывает. Подписанный лист не меняется.
- День курса каждого препарата по листам подряд.
- Печать листа и оборота на А4.
- Методичка: таблица жидкости, пороги билирубина и трансфузии по КР.
