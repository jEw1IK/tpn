# Переезд POSTNEO на сервер в России

Старый сервер `89.169.32.9` стоит за границей (Aeza, Финляндия/Швеция). Данные пациентов —
персональные данные граждан РФ, их запись и хранение должны идти в базах на территории РФ
(152-ФЗ, ст. 18 ч. 5). Поэтому переезд обязателен.

Что переезжает: сайт (главная, калькулятор, шкалы, седация, энтеральное, шпаргалки),
отделение `/kart` с базой и пакет для ПК `/download`. Telegram-бот остаётся на старом сервере:
данных пациентов он не хранит. Старый сервер после переезда переадресует все свои адреса на новый.

Время: около часа. Отделение недоступно 15–30 минут (шаги 2–5), делать вечером.

## 0. Новый сервер

- Провайдер в России, дата-центр в РФ: Selectel, Timeweb Cloud, Yandex Cloud и т. п.
- Ubuntu 24.04, 2 ядра, 2–4 ГБ памяти, 20 ГБ диска.
- Вход по SSH-ключу. Ключи и пароли никому не пересылать.
- Если больница потребует аттестованную инфраструктуру по 152-ФЗ, у тех же провайдеров есть
  защищённый сегмент; скрипт ставится туда так же.

Записать новый IP — дальше он `НОВЫЙ_IP`.

## 1. Установка на новом сервере

```bash
curl -fsSL https://raw.githubusercontent.com/jEw1IK/tpn/main/postneo-app/deploy/setup-ru-server.sh | sudo bash
```

Скрипт ставит nginx, сайт (релизами, с откатом), сертификат на IP, отделение, файрвол
(открыты только SSH, 80, 443) и автообновления безопасности. В конце печатает проверку.

После него открываются `https://НОВЫЙ_IP/postneo/` и `https://НОВЫЙ_IP/kart/`.
**Отделение до переноса базы не открывать**: пустая база показывает страницу создания
администратора.

## 2. Остановить запись на старом сервере и снять копию

На старом сервере:

```bash
sudo systemctl stop postneo-kart-update.timer postneo-kart
sudo systemctl start postneo-kart-backup.service   # копия через службу: она знает путь к базе из /etc/postneo-kart.env
ls -t /var/lib/postneo-kart/backups | head -1      # имя свежей копии
```

Копия делается через `VACUUM INTO`: в ней нет остатков старых открытых записей,
которые могли сохраниться в свободных страницах рабочего файла.

## 3. Перенести копию

На новом сервере (подставить имя файла из шага 2):

```bash
scp root@89.169.32.9:/var/lib/postneo-kart/backups/postneo-ГГГГММДД-ЧЧММ.sqlite /root/
```

Если с нового сервера на старый не пускает — скачать файл к себе на компьютер и залить
на новый тем же `scp`. Файл не пересылать почтой и мессенджерами.

## 4. Подключить базу на новом сервере

```bash
curl -fsSL https://raw.githubusercontent.com/jEw1IK/tpn/main/postneo-app/deploy/import-db.sh -o import-db.sh
sudo bash import-db.sh /root/postneo-ГГГГММДД-ЧЧММ.sqlite
```

Скрипт проверит целостность, покажет число пользователей, пациентов и незашифрованных записей,
сохранит пустую базу нового сервера в `backups/` и запустит отделение.

Проверка: войти на `https://НОВЫЙ_IP/kart/` своим логином и паролем, открыть пациента.
Если скрипт написал про незашифрованные записи — нажать «Зашифровать всё» под администратором.

Потом удалить копию: `sudo shred -u /root/postneo-*.sqlite`.

## 5. Старый сервер: переадресация на новый

На старом сервере, сразу после проверки входа на новом:

```bash
curl -fsSL https://raw.githubusercontent.com/jEw1IK/tpn/main/postneo-app/deploy/retire-old-server.sh -o retire-old-server.sh
sudo bash retire-old-server.sh НОВЫЙ_IP
```

Скрипт выключает на старом сервере сайт и отделение и ставит переадресацию: любой адрес
`http(s)://89.169.32.9/…` уводит на `https://НОВЫЙ_IP/…` с тем же путём. Поэтому закладки врачей,
старые ссылки и приложение для ПК (вход в отделение и проверка обновлений) продолжают работать
без пересборки. Бот не трогается. Прежние конфиги nginx сохраняются в `/root/nginx-before-move-…`.

## 6. Домен

В Reg.ru, «DNS-серверы и управление зоной»:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | `НОВЫЙ_IP` |
| A | `www` | `НОВЫЙ_IP` |

Записи TXT для Яндекса и Google не трогать. Через 15–60 минут на новом сервере ещё раз:

```bash
curl -fsSL https://raw.githubusercontent.com/jEw1IK/tpn/main/postneo-app/deploy/setup-ru-server.sh | sudo bash
```

Скрипт увидит, что домен смотрит на него, и выпустит сертификат на `postneo.ru` и `www.postneo.ru`.

## 7. Новые ссылки для врачей

В больнице домен `postneo.ru` режет фильтр, поэтому на работе ссылка по IP. Старая
`https://89.169.32.9/kart/` продолжит работать через переадресацию, но в инструкции для врачей
и в группе стоит дать новую: `https://НОВЫЙ_IP/kart/`.

## 8. Стереть данные отделения со старого сервера

Через неделю, когда всё работает, на старом сервере:

```bash
sudo bash retire-old-server.sh НОВЫЙ_IP --wipe
```

Стирает базу отделения и все её копии, сборки сайта и отделения. Бот и его файлы
(`/opt/postneo/app`, `/opt/postneo/.env`) остаются, переадресация продолжает работать.
На виртуальных дисках стирание не гарантирует, что старые блоки не останутся у провайдера;
полностью это закрывается только удалением сервера, но он нужен боту.
