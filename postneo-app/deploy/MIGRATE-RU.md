# Переезд POSTNEO на сервер в России

Старый сервер `89.169.32.9` стоит за границей (Aeza, Финляндия/Швеция). Данные пациентов —
персональные данные граждан РФ, их запись и хранение должны идти в базах на территории РФ
(152-ФЗ, ст. 18 ч. 5). Поэтому переезд обязателен.

Что переезжает: сайт (главная, калькулятор, шкалы, седация, энтеральное, шпаргалки),
отделение `/kart` с базой и пакет для ПК `/download`. Telegram-бот остаётся на старом сервере:
данных пациентов он не хранит. Старый сервер после переезда переадресует все свои адреса на новый.

Время: около часа. Отделение недоступно 15–30 минут (шаги 2–5), делать вечером.

## 0. Новый сервер

- Провайдер в России, дата-центр в РФ: Selectel, Timeweb Cloud, Yandex Cloud и т. п.
- Ubuntu 24.04, 2 ядра, 2–4 ГБ памяти, 20 ГБ диска.
- Вход по SSH-ключу. Ключи и пароли никому не пересылать.
- Если больница потребует аттестованную инфраструктуру по 152-ФЗ, у тех же провайдеров есть
  защищённый сегмент; скрипт ставится туда так же.

Записать новый IP — дальше он `НОВЫЙ_IP`.

## 1. Установка на новом сервере

```bash
curl -fsSL https://raw.githubusercontent.com/jEw1IK/tpn/main/postneo-app/deploy/setup-ru-server.sh | sudo bash
```

Скрипт ставит nginx, сайт (релизами, с откатом), сертификат на IP, отделение, файрвол
(открыты только SSH, 80, 443) и автообновления безопасности. В конце печатает проверку.

После него открываются `https://НОВЫЙ_IP/postneo/` и `https://НОВЫЙ_IP/kart/`.
**Отделение до переноса базы не открывать**: пустая база показывает страницу создания
администратора.

## Шаги 2–4 одной командой

На новом сервере, после проверки SSH-доступа к старому и согласования паузы записи.
Подставьте внешний IPv4 нового сервера вместо `НОВЫЙ_IP`. База назначения должна быть пустой:

```bash
curl -fsSL https://raw.githubusercontent.com/jEw1IK/tpn/main/postneo-app/deploy/pull-db.sh -o pull-db.sh
sudo env EXPECTED_NEW_IP=НОВЫЙ_IP bash pull-db.sh
```

Скрипт проверяет внешний IP и пустоту базы назначения, приостанавливает обновления,
останавливает старое отделение, снимает свежую копию, передаёт её сюда, проверяет и подключает.
Пароль root старого сервера вводится в терминале. Для этого SSH-хост должен быть уже проверен
при предварительном подключении. Итоговая копия сохраняется в закрытом каталоге
`/root/postneo-migration`; её точный путь будет в выводе.
При ошибке после начала переноса новое отделение останавливается, а скрипт печатает
команду восстановления старого. Оригинальная база источника не удаляется.
После проверки входа на новом сервере включите его таймер: `sudo systemctl start postneo-kart-update.timer`.
На старом сервере отделение и его обновления остаются остановленными до настройки переадресации.
Ниже те же шаги вручную — на случай, если с нового сервера на старый по SSH не пускает.

## 2. Остановить запись на старом сервере и снять копию

На старом сервере:

```bash
sudo systemctl stop postneo-kart-update.timer postneo-kart
sudo systemctl start postneo-kart-backup.service   # копия через службу: она знает путь к базе из /etc/postneo-kart.env
ls -t /var/lib/postneo-kart/backups | head -1      # имя свежей копии
```

Копия делается через `VACUUM INTO`: в ней нет остатков старых открытых записей,
которые могли сохраниться в свободных страницах рабочего файла.

## 3. Перенести копию

На новом сервере (подставить имя файла из шага 2):

```bash
scp root@89.169.32.9:/var/lib/postneo-kart/backups/postneo-ГГГГММДД-ЧЧММ.sqlite /root/
```

Если с нового сервера на старый не пускает — скачать файл к себе на компьютер и залить
на новый тем же `scp`. Файл не пересылать почтой и мессенджерами.

## 4. Подключить базу на новом сервере

```bash
curl -fsSL https://raw.githubusercontent.com/jEw1IK/tpn/main/postneo-app/deploy/import-db.sh -o import-db.sh
sudo bash import-db.sh /root/postneo-ГГГГММДД-ЧЧММ.sqlite
```

Скрипт проверит целостность, покажет число пользователей, пациентов и незашифрованных записей,
сохранит пустую базу нового сервера в `backups/` и запустит отделение.

Проверка: войти на `https://НОВЫЙ_IP/kart/` своим логином и паролем, открыть пациента.
Если скрипт написал про незашифрованные записи — нажать «Зашифровать всё» под администратором.

Потом удалить копию: `sudo shred -u /root/postneo-*.sqlite`.

## 5. Старый сервер: переадресация на новый

Сначала проверить службы бота и публикаций, виртуальные хосты и маршруты старого nginx.
Старый `retire-old-server.sh` заменяет все активные сайты nginx: при общих маршрутах бота
это может нарушить его работу. Не применять его до разбора конфигурации.

Настроить переход только для сайта и отделения, сохранив маршруты бота и публикаций.
Учесть как старые закладки по IP, так и обращения по домену со старым DNS-кэшем.
До подтверждённого перехода не обещать, что старые ссылки уже работают.
Старое отделение и его автообновления остаются остановленными, чтобы не появились две базы.

## 6. Домен

Если старый сервер уже имеет действующий сертификат `postneo.ru` с обоими именами,
подготовить HTTPS на новом сервере **до изменения DNS**. Требуются уже проверенный SSH-хост
старого сервера, работающий HTTPS по новому IP и исправленный маршрут `/` на `/postneo/`:

```bash
curl -fsSL https://raw.githubusercontent.com/jEw1IK/tpn/main/postneo-app/deploy/stage-domain.sh -o stage-domain.sh
sudo env EXPECTED_NEW_IP=НОВЫЙ_IP bash stage-domain.sh
```

Скрипт передаёт сертификат и ключ непосредственно между серверами по SSH, сохраняет их
с закрытыми правами, добавляет отдельный доменный HTTPS-блок и проверяет оба имени через
локальный `curl --resolve` с проверкой TLS. Резервирует конфигурацию и восстанавливает её
при ошибке. DNS не меняет. Повторный запуск при существующем доменном блоке запрещён.
Вывод `SOURCE_EXTRA_ROUTES` и состояния служб нужно разобрать перед переключением DNS:
при необходимости сохранить доступ к обработчикам бота на старом сервере.

После `DOMAIN_OK` для обоих имён и проверки маршрутов в Reg.ru изменить две записи:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | `НОВЫЙ_IP` |
| A | `www` | `НОВЫЙ_IP` |

Записи TXT и NS сохранить. Дождаться, когда DNS для обоих имён указывает на новый IP;
старые записи могут оставаться в кэшах до истечения прежнего TTL.
Затем на новом сервере выпустить сертификат под управлением местного Certbot:

```bash
curl -fsSL https://raw.githubusercontent.com/jEw1IK/tpn/main/postneo-app/deploy/enable-domain.sh -o enable-domain.sh
sudo bash enable-domain.sh postneo.ru
```

Скопированный для подготовки сертификат сам по себе **не получает автоматического продления**.
После выпуска проверить пути сертификата в nginx, таймер Certbot, deploy-hook перезагрузки nginx
и `certbot renew --dry-run`. Полный установщик сервера ради подключения домена повторять не нужно.
Проверить вход и расшифровку пациента по домену, а затем включить автообновления нового отделения.

## 7. Новые ссылки для врачей

В больнице домен `postneo.ru` режет фильтр, поэтому на работе ссылка по IP. Старая
`https://89.169.32.9/kart/` продолжит работать через переадресацию, но в инструкции для врачей
и в группе стоит дать новую: `https://НОВЫЙ_IP/kart/`.

## 8. Стереть данные отделения со старого сервера

После проверки входа, расшифровки, новых резервных копий и восстановления из них определить
срок хранения старых копий. Отдельно согласовать удаление и точный список файлов, включая
копии в `/root/postneo-migration`, которые не покрывает старый скрипт очистки.
Не применять общий `retire-old-server.sh --wipe` к серверу с общими маршрутами бота.
На виртуальных дисках стирание не гарантирует, что старые блоки не останутся у провайдера;
полностью это закрывается только удалением сервера, но он нужен боту.
