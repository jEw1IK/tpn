# Шпаргалки неонатолога — PDF для телеграм-бота

Генератор одностраничных (точнее, 2–4-страничных) PDF-памяток для работы
у постели пациента и модуль, который раздаёт их из бота.

Сейчас в наборе **13 шпаргалок**. Добавить свою — примерно 20 строк в одном файле,
вёрстку писать не нужно.

---

## 1. Что где лежит

```
cheatsheets/
├── build.py              ← запускаешь это, получаешь все PDF
├── requirements.txt      ← одна зависимость: reportlab
├── manifest.json         ← генерируется сборкой, из него читает бот
├── index.html            ← генерируется сборкой, страница со ссылками
│
├── data/
│   └── bilirubin.json    ← ЕДИНЫЙ ИСТОЧНИК порогов билирубина
├── bilirubin.py          ← расчёт порогов на Python (для бота)
│
├── content/              ← ЗДЕСЬ ЖИВЁТ МЕДИЦИНСКИЙ ТЕКСТ
│   ├── __init__.py       ← список модулей MODULES
│   ├── _data.py          ← строит таблицы из data/*.json
│   ├── gbn.py            ← одна шпаргалка = один файл
│   ├── rodzal.py
│   └── …
│
├── neocheat/             ← движок, трогать не нужно
│   ├── blocks.py         ← «кубики», из которых собирается страница
│   ├── theme.py          ← цвета, шрифты, стили
│   └── render.py         ← вся вёрстка
│
├── fonts/                ← DejaVu Sans, чтобы кириллица работала везде
├── pdf/                  ← готовые PDF (лежат в репозитории)
└── bot/
    ├── catalog.py           ← каталог + кэш file_id, без привязки к фреймворку
    ├── aiogram_router.py    ← роутер aiogram v3: раздача PDF
    ├── bilirubin_router.py  ← роутер aiogram v3: /bili и /ozpk
    └── standalone_bot.py    ← отдельный бот для проверки

../bili/
├── index.html            ← мини-приложение «Калькулятор билирубина»
└── thresholds.js         ← генерируется сборкой из data/bilirubin.json
```

---

## 2. Как собрать

```bash
cd cheatsheets
pip install -r requirements.txt
python build.py                 # собрать всё
python build.py gbn rodzal      # пересобрать только эти две
```

Сборка кладёт PDF в `pdf/`, обновляет `manifest.json` и `index.html`.

Готовые PDF **закоммичены в репозиторий**, поэтому боту reportlab не нужен —
он просто отдаёт файлы с диска.

## 3. Как добавить свою шпаргалку

### Шаг 1. Создай файл `content/moya_tema.py`

```python
# -*- coding: utf-8 -*-
from neocheat.blocks import Callout, Formula, H, KV, Note, OL, P, Sheet, Table, UL

SHEET = Sheet(
    id="moya_tema",                       # латиницей, станет именем файла moya_tema.pdf
    title="Название шпаргалки",
    subtitle="Подзаголовок через · точки",
    category="Дыхание",                   # раздел меню в боте
    button="🫁 Короткая подпись кнопки",
    order=25,                             # чем меньше, тем выше в меню
    summary="Одна строка описания для меню и index.html.",
    blocks=[
        H("1. Первый раздел"),
        P("Обычный абзац. Можно <b>жирным</b>."),
        Table(
            head=["Колонка", "Ещё колонка"],
            widths=[2, 3],                # относительные доли ширины
            align="lc",                   # l / c / r на каждую колонку
            rows=[
                ["Значение", "!! красная ячейка"],
                ["Значение", "+ зелёная ячейка"],
            ],
        ),
        Callout("danger", "Заголовок предупреждения", "Текст."),
    ],
    sources=["Клинические рекомендации МЗ РФ «…»"],
)
```

### Шаг 2. Впиши имя модуля в `content/__init__.py`

```python
MODULES = [
    "rodzal",
    "moya_tema",   # ← сюда
    …
]
```

### Шаг 3. Собери

```bash
python build.py
```

Всё. Шпаргалка появится в PDF, в `manifest.json`, в меню бота и на `index.html`.

## 4. Справочник по блокам

| Блок | Для чего | Пример |
|---|---|---|
| `H("текст")` | Заголовок раздела — синяя плашка | `H("3. Дозы")` |
| `P("текст")` | Абзац | `P("Общий билирубин, мкмоль/л.")` |
| `UL("а", "б")` | Маркированный список | |
| `OL("шаг", "шаг")` | Нумерованный список — для алгоритмов | |
| `Table(head=…, rows=…)` | Таблица | см. ниже |
| `Callout(тон, заголовок, текст)` | Выделенный блок с цветной полосой слева | `Callout("danger", "Стоп", "…")` |
| `Formula("формула", "пояснение")` | Формула в рамке по центру | |
| `KV(("ключ","значение"), …)` | Компактная сетка пар в две колонки | |
| `Note("текст")` | Мелкая серая сноска | |
| `Rule()` | Тонкая линия | |
| `Spacer(6)` | Вертикальный отступ | |
| `PageBreak()` | Принудительный перенос страницы | |

**Тона** для `Callout` и подсветки: `info` (синий), `ok` (зелёный),
`warn` (жёлтый), `danger` (красный), `muted` (серый).

### Подсветка ячеек таблицы

Маркер ставится **в начало текста ячейки, через пробел**. В PDF он не виден.

| Маркер | Цвет |
|---|---|
| `"!! текст"` | красный |
| `"! текст"` | жёлтый |
| `"+ текст"` | зелёный |
| `"~ текст"` | синий |

Пробел обязателен — иначе `+15 мл` и `~2 ч` превратились бы в подсветку.

### Строка-подзаголовок внутри таблицы

Если элемент `rows` — не список, а **строка**, он растягивается на всю ширину
таблицы и работает как разделитель группы:

```python
Table(
    head=["Категория", "Критерий"],
    rows=[
        "!! Абсолютные показания",       # ← красная строка-разделитель
        ["Клиника", "Энцефалопатия"],
        "! Относительные показания",
        ["Динамика", "Прирост 6,8–8,5"],
    ],
)
```

### Спецсимволы

Писать `<`, `>` и `&` можно как есть — движок экранирует их сам,
пропуская только теги разметки `<b>`, `<i>`, `<u>`, `<br/>`, `<font>`,
`<super>`, `<sub>`. То есть `Hb < 100 г/л` и `<b>жирный</b>` в одном
абзаце работают одновременно.

## 5. Калькулятор билирубина

Мини-приложение лежит в `bili/` и открывается из бота кнопкой.

Что умеет:

- **Пороги ФТ и ОЗПК** по гестационному возрасту, часам жизни и факторам риска.
  Для ≥ 35 нед значение **интерполируется** между опорными точками, то есть
  на 36 или 60 часах даёт настоящий порог, а не соседнюю клетку таблицы.
  Для < 35 нед — диапазон по ГВ: при факторах риска берётся нижняя граница.
- **Номограмма** с кривыми выбранной группы риска и точкой пациента.
- **Почасовой прирост** с трактовкой и оценкой, через сколько часов
  билирубин дойдёт до порога ОЗПК при текущем темпе.
- **Отношение билирубин / альбумин** с порогом для своей категории.
- **Объём ОЗПК**: общий, эритроцитная взвесь, СЗП, объём за цикл,
  частичное ОЗПК при отёчной форме.
- **Трансфузия эритроцитной взвеси**: порог по возрасту и респираторной
  поддержке, расчёт объёма и времени введения.
- Переключение **мкмоль/л ↔ мг/дл** — при переключении уже введённые значения
  пересчитываются, а не меняют смысл.

### Один источник цифр

Все пороги лежат в **`data/bilirubin.json`**. Из него берут данные сразу трое:

| Кто | Как |
|---|---|
| PDF-шпаргалка по ГБН | `content/_data.py` строит таблицы при сборке |
| Мини-приложение | `build.py` генерирует `bili/thresholds.js` |
| Бот (`/bili`, `/ozpk`) | `bilirubin.py` читает JSON напрямую |

Поэтому разойтись они не могут: правишь JSON, запускаешь `python build.py` —
меняется везде. Логика расчёта в `bilirubin.py` и в `bili/index.html`
продублирована на двух языках, и округление специально приведено к одному
виду («половина вверх»), чтобы бот и калькулятор давали одинаковые цифры.

### Где менять пороги

```jsonc
// data/bilirubin.json
"term": {
  "hours": [0, 24, 48, 72, 96, 120, 168],   // опорные точки
  "phototherapy": {
    "low":  [137, 205, 257, 308, 359, 359, 359],
    "med":  [111, 171, 222, 257, 291, 308, 308],
    "high": [86, 137, 188, 231, 239, 257, 257]
  },
  "exchange": { … }
}
```

Добавить опорную точку — допиши час в `hours` и по значению в каждый ряд.
В PDF выводятся только часы из `PDF_HOURS` в `content/_data.py`,
калькулятор использует все.

## 6. Подключение к телеграм-боту

### Вариант A — бот на aiogram v3 (две строки)

Скопируй папку `cheatsheets/` в репозиторий бота и добавь:

```python
from cheatsheets.bot.aiogram_router import cheatsheets_router
from cheatsheets.bot.bilirubin_router import bilirubin_router

dp.include_router(cheatsheets_router)
dp.include_router(bilirubin_router)
```

Появятся команды:

| Команда | Что делает |
|---|---|
| `/shpory` | Меню по разделам → список шпаргалок → PDF в чат |
| `/shpory гбн` | Поиск по названию и описанию |
| `/bili` | Кнопка, открывающая калькулятор билирубина |
| `/bili 36 24 190 гбн` | Пороги текстом, без открытия окна |
| `/ozpk 3200` | Объём ОЗПК по массе тела |

Адрес мини-приложения задаётся переменной окружения `BILI_WEBAPP_URL`
(по умолчанию `https://jew1ik.github.io/tpn/bili/`).

Не забудь добавить команды в меню бота:

```python
await bot.set_my_commands([
    BotCommand(command="shpory", description="📄 Шпаргалки в PDF"),
    BotCommand(command="bili",   description="🧮 Калькулятор билирубина"),
    BotCommand(command="ozpk",   description="🩸 Объём ОЗПК по массе"),
])
```

### Вариант B — любой другой фреймворк

`bot/catalog.py` не зависит от телеграм-библиотеки:

```python
from cheatsheets.bot.catalog import Catalog

catalog = Catalog()
catalog.categories()              # ['Родзал и реанимация', 'Дыхание', …]
catalog.by_category("Дыхание")    # [Cheatsheet, …]
catalog.get("gbn").path           # путь к PDF на диске
catalog.search("озпк")            # поиск по названию и описанию

# кэш file_id, чтобы не заливать один PDF по многу раз
catalog.file_id("gbn")                     # None или сохранённый file_id
catalog.remember_file_id("gbn", file_id)   # запомнить после первой отправки
```

Кэш инвалидируется автоматически: в нём хранится `sha256` файла, и после
пересборки PDF старый `file_id` перестаёт использоваться.

### Вариант C — ссылкой, без заливки файла

Если репозиторий опубликован через GitHub Pages, PDF доступны по прямым ссылкам:

```
https://jew1ik.github.io/tpn/cheatsheets/pdf/gbn.pdf
https://jew1ik.github.io/tpn/cheatsheets/            ← страница со всеми
```

Ссылка на каждую шпаргалку лежит в `manifest.json` в поле `url`.
Базовый адрес задаётся константой `PAGES_BASE` в `build.py`.

### Проверить, не трогая основной бот

```bash
pip install aiogram
export BOT_TOKEN=123456:AA...
python -m cheatsheets.bot.standalone_bot
```

## 7. Что важно помнить про содержание

Шпаргалки — **памятки для быстрой сверки**, а не нормативный документ.
Дозы, пороги и схемы нужно сверять с действующей редакцией клинических
рекомендаций МЗ РФ, инструкциями к препаратам и протоколами отделения.
Источники перечислены в конце каждого PDF, дисклеймер — в подвале каждой страницы.

Правки вносятся в файл `content/<id>.py` и вступают в силу после `python build.py`.
