## 1. Что это

Заказчик — врач-неонатолог, автор телеграм-бота **@postneo1_bot**
(«ПОСТ·НЕО | Инструменты неонатолога»). Начиналось с PDF-шпаргалок,
выросло в отдельный проект: генератор PDF, мини-приложение, поиск по
клиническим рекомендациям и готовый бот целиком.

## 3. Ключевые решения и почему именно так

**Данные отдельно от вёрстки.** Всё, что можно перепутать при правке
(пороги билирубина, дозы, параметры ИВЛ), лежит в `data/*.json` и попадает
и в PDF, и в мини-приложение, и в ответы бота. Разойтись они не могут.

**Проверки на сборке.** `content/_data.py` при импорте сверяет лестницу
порогов билирубина: ФТ < интенсивная ФТ < ОЗПК в каждой клетке, ряды не
убывают с возрастом. Опечатка в цифре роняет сборку, а не уезжает в PDF.

**Источники в каждой шпаргалке.** ID рекомендации и дата размещения —
чтобы врач мог проверить. ID теперь ещё и в `manifest.json`: по ним бот
показывает шпаргалку рядом с найденной рекомендацией.

**Расчёты — в мини-приложениях.** Шкалы и питание считаются там: пунктов
много, их удобнее отмечать пальцем. Исключение — разведение мидазолама
и фентанила: одна масса и правило, поэтому «мидазолам 1200» отвечает и прямо
в чате, а кнопка под ответом открывает калькулятор с теми же числами.
Калькулятор билирубина убран по решению автора — осталась шпаргалка `gbn.pdf`.

**Разведение — по правилу врача.** Автор думает так: «хочу, чтобы 0,3 мл/ч
были 0,03 мг/кг/ч — до скольки развести ампулу?». Калькулятор устроен ровно
так же, а примеры из его переписки (`tests/dilution_cases.json`) — эталон,
на котором проверяются и бот, и приложение. Инфузионных доз седации в КР
МЗ РФ нет (только болюсы для интубации в А3.9 КР 912_1), поэтому обычные
диапазоны в `data/sedation.json` — из практики отделения и инструкции
к мидазоламу (до 32 нед — 0,03, после — 0,06 мг/кг/ч).

**Седация вложена в шпаргалки.** `sedation_router` подключён внутрь
`cheatsheets_router`, а тот на сервере уже стоит раньше собственного поиска
бота. Поэтому калькулятор заработал бы даже без правки bot.py; правка
(`deploy/patch_bot.py`) только ставит кнопку и команду в меню.

**Поиск рассчитан на живой запрос.** «гбн», «P23.0», «сурфактант», опечатка,
латинская раскладка — всё это разные ветки в `search.py`, с разными баллами,
так что точное совпадение кода никогда не проигрывает нечёткому.

## 4. Что проверено

- 55 проверок в `tests/test_bot.py`: команды, кнопки, колбэки, поиск, дозы,
  седация, поведение в группе (там web_app-кнопок быть не должно).
- 98 проверок в `tests/test_dilution.py`: 17 примеров из переписки автора
  (468 г → 35,6 мл, фентанил 1180 г → 8,5 мл и т.д.) и граничный случай
  проходят и бот, и мини-приложение, результаты совпадают построчно.
- 15 проверок в `tests/test_patch_bot.py`: правка модели живого bot.py,
  повторный прогон без изменений, бот после правки отвечает калькулятором
  на «мидазолам 1200», а прочий текст уходит в его собственный поиск.
- Мини-приложения живут на GitHub Pages, все открываются.
- Расчёты калькулятора ПП сверены до цифры после слияния вкладок.

## 5. Что требует вычитки врачом

- Инотропы: приложение А3.6 КР 912_1 перенесено в `data/inotropes.json`
  и выведено в шпаргалке по сепсису. В `content/inotropes.py` таблица доз
  пока прежняя, по международным источникам — стоит заменить на А3.6,
  чтобы в продукте не было двух разных таблиц.
- `content/vent.py` делит стартовые параметры ИВЛ по массе, а приложение
  А3.7 КР 912_1 — по течению болезни. Данные уже лежат в
  `data/ventilation.json`, `start_vent_table(only=[...])` готова.
- Показания к сурфактанту в `rds_surfactant.py` возвращены к прежней
  редакции по просьбе автора; от КР 340_2 они отличаются в части
  профилактики при сроке ≤26 недель.

## 6. Что осталось

1. Дописать инотропы и параметры ИВЛ по КР 912_1 (см. выше).
2. Набор по КР закрыт: апноэ (933_1), БЛД (377_2), ВЖК (948_1), ТТН (951_1),
   сепсис (912_1), полицитемия (909_1), геморрагическая болезнь (906_1),
   ретинопатия (107_2), холестаз (959_1), анемия недоношенных (661_2),
   кандидоз (944_1), ВДГ (840_1), ЦМВ (260_2), ГЭРБ и срыгивания (950_1,
   962_1), здоровый новорождённый (924_1). Следующие кандидаты — темы,
   на которые КР есть в `data/guidelines.json`, но шпаргалки пока нет:
   ВИЧ (459_2), ВДКН (914_1), бронхиолит и РСВ (360_3), родовая травма
   (935_1), менингит (995_1).
3. Шкалы: PIPP-R. Сделаны nSOFA, NIPS, N-PASS, VIS, NEOMOD и её
   модифицированный вариант (приложения Г2–Г3 КР 912_1), Сарнат (Г2 КР 908_1).
4. Канал — https://t.me/postneo01, лежит в `data/brand.json`; переопределяется
   переменной окружения `CHANNEL_URL`. Подпись автора печатается второй
   строкой подвала каждой шпаргалки (`neocheat/render.py`, `_draw_credit`).

**Дальняя цель автора** — экосистема: расчёт ПП с запоминанием пациентов,
база пациентов отделения, агент для написания дневников, референсные
значения. Структура под это заложена: данные отделены от представления,
расчёт продублирован для бота и веба.

## 7. Как продолжить

```bash
git clone https://github.com/jEw1IK/tpn.git
cd tpn/cheatsheets
pip install -r requirements.txt        # reportlab, для сборки PDF
python build.py                        # пересобрать PDF, manifest, scales/scales.js
pip install -r requirements-bot.txt    # aiogram, для бота
python tests/test_bot.py               # прогнать бота без сети и токена
```

Читать в таком порядке: `README.md` → `deploy/README.md` → этот файл.
